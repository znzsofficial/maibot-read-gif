# GIF 动图识别（Read GIF）— Neko maintenance fork

基于 [fabiocsa/maibot-read-gif](https://github.com/fabiocsa/maibot-read-gif) 的薄维护fork，
保留完整上游历史、作者和MIT许可，不是独立原创。原插件思路参考
[dsh-read-animation](https://github.com/NeoHotaru/dsh-read-animation)，归属见 [NOTICE.md](NOTICE.md)。

当前维护版 **0.2.1**，要求 **MaiBot >=1.3.19、SDK >=2.20.0、Python >=3.12**。
插件ID仍为`github.fabiocsa.read-gif`，不与原版双开，不更换原数据目录。

## 做什么

- 检测入站image/emoji中的GIF、动画WebP、APNG；静态图跳过，不支持file附件或MP4/WebM。
- 按累计时长采样（最多8帧），生成带帧号/时长的单张帧板，调用宿主已有`vlm`任务。
- **原消息不改写**：生成描述不再追加为用户TextComponent，不写进原聊天记录或原消息学习输入。
  描述保留在512条/15分钟内存索引中，仅在Planner/Replyer请求前以独立、不可信的派生Item补入。
- 普通聊天按真实会话和消息ID关联；共享Focus从Host的reply工具Schema读取允许会话，
  只认真实UserMessageItem首段的Host消息前缀；不从用户正文/群名猜归属。Replyer兼容Host原始目标消息ID。
  无法可靠匹配就跳过，不修改工具调用/输出/原Item/路由或provider replay。

描述仍可能影响模型的后续回复或其自然记忆，不能宣称完全不会间接进入摘要；
这里保证的是插件不把描述伪装成入站原话，不额外写真实消息、表达学习或黑话记录。
15分钟到期/进程重载后缺失的关联不从聊天正文猜回；描述内容缓存与该短期索引是不同用途。

## 本次加固

- 入站识别使用BLOCKING/NORMAL，晚于门卫BLOCKING/EARLY；被门卫abort的消息不会进入本插件解码/VLM。
  原生表情标签与本插件动态描述仍分工独立，不宣称两条识别链全局去重；不关闭原生图片/表情注册。

- 同内容/配置的并发消息共享一次解码及视觉任务，取消一个等待者不取消其他等待者。
- 整体准入有界；解码与模型在途各受并发上限约束，取消的解码线程直到真正结束仍占名额。
  输入先检查Base64长度再分配解码字节；帧数扫描不先读Pillow的无界`n_frames`，
  有单帧/累计解码像素、扫描帧数、实际帧板像素与协作截止检查；APNG独立poster不当动画帧。
- 热更新保留单份缓存/在途计数，配置快照与generation隔离旧结果；卸载关闭准入，旧任务不回写新配置描述。
- `mentioned`读取入站时已存在的适配器标志、结构化@目标与引用作者，私聊仍可触发；
  不再仅依赖更晚才由Maisaka补齐的顶层标志，也不把任意@别人或正文中的ID当触发。
- 缓存每次命中检查TTL，成功描述立即原子保存；读取损坏/不支持版本/保存失败时保留文件并停止新付费识别。
- 默认输出额度仍 **4096**；`vlm.retry_empty_response=false`，不因任意空正文盲目提高额度。
  管理员明确打开时，仅已完成的空正文可升额度补试一次，最多8192；超时/未知不重试。

## 超时、费用与未知请求

首次识别仍是入站阻塞步骤：默认每条消息最多2个动图、单次等待20秒、消息总预算40秒、Hook45秒。
即使最终不回复，新动图识别也可能计费；宿主模型任务本身仍可有既有候选切换/重试。
插件不代改模型、超时、安全设置、名单、群Focus或生图/语音/主动发言策略。

**本地等待超时不等于Host/上游已取消或未收费**。超时后保留实际能力调用的在途占用，
不重发同图，迟到的明确成功可写缓存供后续使用；配置变化后不写旧描述。
断连/异常/卸载后无法确定结果的记录持久保存为unknown，占用并发名额，不定时自动清空或跨重启重放。
到达上限会停止新识别、保留正常原图聊天。需管理员确认Host实际请求已结束/核对账单后再维护对应记录，
不要靠删缓存、提高并发或重启绕过防重。插件不修改宿主通用RPC取消协议，也不承诺硬取消远端请求。

`description_cache.json`升级为v2（同一文件同时保存描述和请求状态），兼容读取旧v1描述；
旧描述保留但新完整配置指纹不承诺复用。不要用旧0.1.2直接读取/覆盖v2状态来回滚，
应保留当前现场并匹配源码/配置/数据恢复，不丢弃unknown记录。

## 配置

仍由SDK生成/迁移`config.toml`，不把运行配置提交进Git。原有值保持，新增配置版本1.3.0。

| 配置节 | 要点 |
| --- | --- |
| plugin | enabled、config_version |
| trigger | all / mentioned / off；图片/表情开关；每消息识别上限（默认2） |
| frames | 默认8帧、512长边、4列、110万帧板像素；输入8MiB、最多3000扫描帧/60秒；新增累计解码1.6亿像素预算 |
| vlm | 默认宿主vlm任务、不指定模型；4096Token、20秒、300字；新增retry_empty_response默认false |
| inject | 前缀、元信息、采样提示；现在用于请求派生上下文，不改写原消息 |
| cache | 描述缓存1000条/30天；关闭描述缓存不关闭付费请求防重记录 |
| perf | max_concurrent默认2；max_pending默认8，准入满即跳过，不无界排队 |

Base64/RPC与模型输入是不同预算。本fork**不扩宿主binary**：现行维护宿主的binary只覆盖Planner/Replyer请求前Hook，
不是本插件入站消息或llm.generate能力往返的通用优化；它们仍受宿主普通Envelope预算约束。
超过整帧上限可能在插件得到载荷前失败，不能承诺插件一定能自行降级。
宿主若在Hook前已将大动图压成静态JPEG，插件无法恢复丢失动画；不为此关闭宿主图片保护。
文件型图片/视频取址是另外的问题，本插件不取代Files/Video或修复QQ协议端。
